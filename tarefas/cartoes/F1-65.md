## Contexto
Achado 4 da revisão do F1-17 (info) e decisão do dono: `VfsFile{}.resolve(...)` e `.size()` desreferenciam `vfs_ == nullptr` (`sw-core/include/swarmstream/vfs.hpp:118`, `vfs.cpp:211-218`). `[[nodiscard]]` e `valid()` mitigam, mas a precondição não está escrita no header, e o F1-60 receberá o `VfsFile` por fora. Revisão independente do F1-17: https://github.com/Alexandremocmg/swarmstream/pull/25#issuecomment-6510220898.

## Escopo
**Entrega documental (feita no PR do [F1-63](F1-63.md), sem outro PR):** documentar no `vfs.hpp` a precondição de uso de `VfsFile`/`VfsDir`/`VfsSpans`. **Verificação futura na API C:** a validação de handles é **critério de aceite obrigatório e testado do F1-60**, não pré-requisito deste cartão. Sem verificações indiscriminadas no caminho quente.

## Critério de aceite
- Precondições escritas no `vfs.hpp` e conferidas na revisão do PR do F1-63.
- A prova de que a API C não repassa handle inválido é critério do [F1-60](F1-60.md) (não é verificada aqui).

## Fora do escopo
Implementar a API C (F1-60); mudar semântica do ADR-0017.
