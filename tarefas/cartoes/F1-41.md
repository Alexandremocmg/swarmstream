# F1-41: Alinhar a spec 03 (§7.1, §7.2, §8) ao ADR-0012: format_version só do envelope, min_reader no payload

- **Estado:** EM_REVISAO
- **Fase:** F1a
- **Papel sugerido:** R1
- **Sessão:** Arquiteto
- **Modelo e esforço sugeridos:** Sonnet 5.5, esforço alto

- **Depende de:** nenhuma
- **Linha do backlog:** novo (apontado pela sessão Arquiteto, R1, em 2026-10-18; ainda não está em [docs/11](../../docs/11-backlog-inicial.md))

## Critério de aceite
O documento [03](../../docs/03-formato-de-conteudo.md) passa a dizer o que o [ADR-0012](../../docs/adr/0012-serializacao-do-manifesto.md) (item 5) decidiu: `format_version` do envelope versiona **só o envelope** e é conferido por igualdade; a compatibilidade do **payload** é dada por `min_reader`, lido depois da assinatura, e o leitor recusa com `SW_E_MANIFEST_UNSUPPORTED` se `min_reader` for maior que a versão suportada. Os passos do §8 ficam na ordem em que o `min_reader` é de fato consultado (hoje o passo 1 recusa um `format_version` desconhecido e o `min_reader` nunca chega a ser lido). Vetores de teste afetados ([sw-pack/testdata](../../sw-pack/testdata/README.md)) são atualizados e o PR mostra `verify_vectors.py` verde.

## Pedido
Ainda não há pedido pronto. É mudança de **documentação** (entra por PR). **Fazer antes ou junto da F1-04**, porque o leitor e o gerador do manifesto vão implementar esta regra.

## Evidência
O que o 03 passa a dizer (critério de aceite):
- §7.1: `format_version` versiona só o envelope e é conferido por igualdade (v0 aceita só `0`; diferente ⇒ `SW_E_MANIFEST_UNSUPPORTED`). A compatibilidade do payload é dada pelo `min_reader`, lido **depois da assinatura**, no passo 4; maior que a revisão suportada ⇒ `SW_E_MANIFEST_UNSUPPORTED`.
- §7.2: regra de evolução do payload por `min_reader` (o envelope não muda); campos fixos para sempre.
- §8: as validações são o passo 5, depois da sondagem do `min_reader`; o antigo item 11 saiu da lista, porque depois do verificador já seria tarde para dar o erro certo.

Vetores (Windows 11, Python 3.14.2, OpenSSL do Git for Windows, 2026-10-18), em `sw-pack/testdata`:
```
$ py -3.14 gen_vectors.py
wrote ...\sw-pack\testdata\vectors-v0.json 61678 bytes
$ py -3.14 verify_vectors.py
127 checks, 0 failures            (antes: 111; +1 caso de envelope, +15 da sondagem)
$ py -3.14 test_properties.py
Ran 5 tests in 9.181s ... OK
$ python -I verify_chunker_r1.py
TODOS OK
```
Os valores antigos do JSON não mudaram: o diff só acrescenta casos.

Conferência externa da sondagem, com o runtime oficial `flatbuffers` 25.12.19 para Python: ele lê `min_reader` = 0, 1 e 0 (ausente) nos três payloads válidos, e a sondagem do verificador lê 0, 1 e 7 em buffers gerados pelo `Builder` oficial.

**Fora deste cartão:** o `Verifier` do FlatBuffers não foi rodado sobre os payloads mínimos (não há `flatc` nesta máquina); eles cobrem só o passo 4. O vetor de um payload completo continua pendente do `sw-pack` (F1-04). O comentário de `SW_E_MANIFEST_UNSUPPORTED` no `swarmstream.h` cita "03 §8"; o §8 manteve uma nota que aponta o passo 4, para não mexer no header congelado.
